<h1>Pods</h1>
Pods are the smallest, most basic deployable unit in kubernetes, acting as a wrapper around one or more containers taht share storage and network resources.

Here is the layers
```console
1. Cluster
2. Node
3. Pod
4. Container
```
The most common usage are `single - container pod`. The pod is wrapper around a single application container (like a web server or database). To scale the app, you need more ods rather than adding more containers to one pod.

Anther usage is `multi - container pod`. Pod can hold a main application container alongside tightly coupled helped containers. For example, a main web server container might write logs to a share volume while a `sidecar` container read those logs and sends them to a monitoring service. 

<h3>Running Pods </h3>
To create a pod in Kubernetes, there are two ways to do it.
1. Use the `kubectl` run command to spin up a pod directly from the command line without creating a configuration file.
```console
kubectl run nginx --image nginx
```
--image nginx: the container image to pull from the container registy (e.g., Docker Hub).

2. For tracking changes and managing production infrastructure, define your pod inside a .yaml file.

```console
apiVersion: v1
kind: Pod
metadata:
  name: my-nginx-pod
  labels:
    app: web-server
spec:
  containers:
  - name: nginx-container
    image: nginx:latest
    ports:
    - containerPort: 80
```

Then, apply the file to your cluster.
```console
kubectl apply -f pod.yaml
```
<h3>Pods commands</h3>
List Pods
```console
kubectl get pods
```
Get Information about the pod
```console
kubectl describe pod myapp-pod
```
